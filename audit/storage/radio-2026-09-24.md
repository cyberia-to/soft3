# Radio file transfer over BBG

The next storage slice connects Radio's existing QUIC router to host-provided
file sources and sinks. The `cybergraph-radio` adapter persists received parts
through the same BBG owner as application history and resumes from its coverage.

| owner | implementation revision | evidence |
|---|---|---|
| Radio | `fe72dbd2f15370bfc333709d4870cb2f2b1d0d15` | [[radio/audit/storage/radio-2026-09-24/README|Framing, authorization, deadlines and admission checks]] |
| Cybergraph | `c4854a24e90df1f4d88d6e25ed6ef854b2714a11` | [[cybergraph/audit/storage/radio-2026-09-24/README|Live transfer interruption, both backend directions, reopen and publication]] |

The linked receipts pin commands, locks, source closure and output checksums.
They demonstrate an interrupted live request, both owners reopening while the
old transport is stopped, recovery of acknowledged parts and fetching only the
missing remainder. A verified file can then be retained with its application
head. Rejected peers and substituted content cannot produce that publication.

S5 is now implementing in the [project](../../roadmap/storage/README.md).
[A4 evidence](../../roadmap/storage/acceptance.md#current-local-evidence) applies
to the opt-in protocol. The old BAO/store path remains until content-aware
migration and product cutover; no whole-package qualification is implied.

The adapter preserves existing Blob identity and stages complete ranges before
full-file verification. S1 still owns structural identity and sparse-range proofs.
Foculus orchestration, node/Cyb assembly, remote receipts, FS, Vault recovery and
retention-aware GC remain tracked work. The tests use local APFS storage and
authenticated loopback connections, with relay/external discovery disabled.
