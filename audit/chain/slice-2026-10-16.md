# the vertical slice of the phase-1 root chain — 2026-10-16

One block from genesis to a second machine, locally: the consensus kernel
(#189), the reference miner (#186) and the wire (#187) in one binary, three
nodes on one machine, every block mined by `soft3 mine --backend cpu`
against a node's `/template` + `/submit`, every header, body and transaction
crossing the radio wire to the other nodes and validated there by the
kernel. Requirements: `specs/chain.md`, `specs/chain-wire.md`,
`specs/chain-conformance.md`. Earlier receipts: `audit/chain/net-2026-10-15.md`
(the wire on its stand-in), `audit/chain/mine-2026-10-15.md`,
`audit/chain/conformance-2026-10-16.md`.

## what changed

- main: #186 merged on the kernel (`4527df7`, merge of
  `feat/chain-mine-on-kernel` = #186 + the swap f1f4e94: the miner asks
  `chain::{header, pow, daa}`, its local ASERT copy is gone).
- #187 brought onto main as one squashed commit (the branch carried a merge
  of main whose own changes a commit-by-commit rebase would drop), then:
  - `chain/net/devchain.rs` deleted; `chain/net/kernel.rs` implements the
    wire's port `ChainView` over the kernel's `ChainApi`: header-first
    acceptance, `NeedBodies` (the wire fetches the named bodies from the
    peer and resubmits, `gossip::apply_fetched`; IBD takes the gap by
    ranges), `FutureTime` held and retried each sync tick, `DeepFork` /
    `Checkpoint` logged and never scored, `ChainError::Block` scores the
    serving peer +10, tip-moved events carry the reorged-out bodies, a
    main-chain txid index for `GET /tx/{txid}`. Headers and u256 cross as
    their wire bytes; a test pins header ids, txids, bodies and tx roots on
    both codecs.
  - mempool admission asks the kernel (`validate_tx` with the neuron's lower
    pending nonces); a nonce gap inside the window is not scored, a nonce
    beyond it is (+10). The kernel's `validate_tx` now checks the signature
    before nonce, fee and balance — chain-wire §4's order; the adversarial
    tx flood (unsigned junk at fee 0) was going unscored without it.
  - HTTP §7 on the kernel: `/tip` and `/template` rendered by
    `Tip::json` / `Template::json`; `/nonce` `{neuron, nonce, confirmed}`;
    `POST /tx` `{txid, kind, size, fee, account, nonce}` (already present =
    200); `GET /tx/{txid}` `{txid, kind, tx, height|"mempool", block, index}`,
    404 `{"error":"unknown"}`; `POST /submit` 200 / 409 stale / 422 with the
    kernel's reason. `/status` `genesis` is the chain id (what the wallet
    signs for), `genesis-block`, `next-bits` from ASERT, `finalized`.
  - the node no longer mines (`--mine/--solo/--miner`, `/dev/mine` gone):
    mining is `soft3 mine`. `soft3 chain genesis-dev` writes a real
    `GenesisFile` (kernel-checked, launch names refused), `soft3 chain
    key|tx` sign with `soft3::wallet::Signer`.
  - gossip topic loops survive a lagged receiver instead of ending.
  - `[profile.dev.package.cyber-hemera] opt-level = 3`: tests mine real
    blocks at the floor target on debug builds.
  - `scripts/chain-fleet.nu`: miners are `soft3 mine` processes; every pid
    it spawns is recorded in `$work/pids` and killed by pid — the
    `pkill -f` is gone.

Test chain: `dev`, `bits = POW_LIMIT_BITS` (`0x1e100000`, 2^20 expected
hashes, the easiest target the kernel accepts outside `cfg(test)`), genesis
time two hours back so ASERT sits at the floor for the first ~240 blocks.
No launch genesis is touched; `genesis-dev` refuses `pussy`, `bostrom`,
`pussy-rc`.

Hash: hemera 0.3 (`hemera d5f0a09`). Every hash on the slice goes through
the hemera API (`hemera::hash`, the kernel's `hash32`, the miner's sponge
view); the move to hemera 0.4 (profile #15) re-blesses PoW vectors, the
genesis particle and `chain.snap` in its own sweep.

## what the deploy to cyberproxy, deimos and jupiter still needs

- a release carrying #187 on the kernel (`cargo install soft3 --version
  <phase-1>`), built against pins that build: bbg needs its fjall vendoring
  on master (or soft3 moves off `bbg/rs/vendor/fjall`), and the
  stack-chain-genesis gate needs those 3 warnings gone to turn green.
- the launch genesis files from `soft3 genesis build` with the final
  params, the hemera 0.4 re-bless done, and the ids pinned in
  `chain::params::CHAINS`; until then `--genesis FILE` on every machine,
  byte-identical (step C T−15).
- miners: the nodes do not mine. Someone runs `soft3 mine --node
  http://127.0.0.1:7781 --address <neuron>` (Metal/WebGPU/CPU) against at
  least one node at genesis, or block 1 never comes.
- endpoint ids (`soft3 node id`) collected into `peers.toml` on each box,
  ufw for 7791/udp, nginx snippets (README step A6), jupiter's root steps
  by the owner (no sudo).
- not exercised here: three real machines over the internet (NAT, relay
  off, clock skew), a replay at a real height (restart replays every body;
  tens of blocks took seconds here), and `best_header` / `missing_bodies`
  scanning the in-memory store on each call — fine at slice size, to index
  before long chains.
